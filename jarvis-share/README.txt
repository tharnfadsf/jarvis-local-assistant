J.A.R.V.I.S. Desktop Assistant
================================

Launch
------
Double-click the JARVIS shortcut on the Desktop, JARVIS.exe, or Start-Jarvis.bat. The Windows desktop host starts the local Node bridge and opens the command center. The host can start at Windows sign-in hidden in the notification area; double-click its tray icon to show the interface. Closing the window keeps the host in the tray. The tray Quit command stops the app and its bridge. The HIDE TO TRAY button hides the window to the tray icon without stopping anything: voice listening keeps running while hidden (the window uses flags that prevent background throttling), and clicking the tray icon restores the window and verifies the microphone is still alive, restarting it if needed. Check the voice diagnostics log after restoring if anything seems quiet.

If the bridge does not start, inspect %LOCALAPPDATA%\JARVIS\logs\desktop.log. Node.js and Microsoft Edge are required. The bridge binds to loopback and does not expose a public listener.

Voice
-----
Enable Always Listen (on by default on a new profile) and allow microphone access. Say “Jarvis, open Steam” or say “Jarvis” and give the request within 10 seconds, or in one sentence, for example “Jarvis, play Magnetic”. Normal conversational volume works; you do not need to raise your voice. Background speech is ignored unless it follows the wake phrase. The offline Whisper English model transcribes short microphone phrases locally; Edge's online speech recognition is not used.

After JARVIS answers a finished request, it returns to wake-word standby: say “Jarvis” again for anything new. The no-wake-word follow-up window opens only in two cases — right after the “Yes, Sir?” acknowledgement, and while a multi-turn workflow is waiting for your answer (for example a calendar, email, or Discord question). That window closes after roughly 15 seconds of inactivity, or immediately once your reply is accepted. Say “Stop talking”, “Be quiet”, or “Silence” to stop JARVIS speaking; that is different from “Stop the music”, which controls playback.

You can send Discord messages by voice. “Jarvis, message Alex on Discord”, “DM Alex”, or “Send Alex a Discord message” resolves the contact from discord-contacts.json or a shared server, then asks what to send if the message body was not spoken. The bot token belongs in the local .env file. Nothing is sent without the body and a resolved recipient.

Reminder and event notifications over Discord need a channel webhook, which is separate from bot DMs. In the Discord channel settings create a webhook, then in the local .env file set JARVIS_DISCORD_WEBHOOK_URL to the webhook URL and (optionally) JARVIS_DISCORD_MENTION_ID to your numeric Discord user ID for a personal mention. If a webhook URL was ever pasted into chat, treat it as compromised: delete it in Discord and create a fresh one — never reuse an exposed URL. With the webhook set, creating a reminder or event sends one confirmation message, and a second message arrives when the time comes (the bridge checks every 30 seconds, so it must be running). Say “ping me” for an instant ping with your mention, or “test the webhook” to verify delivery. Overdue-by-more-than-6-hours items are marked missed, never spammed; failures retry at most 3 times and never delete the schedule. Without the webhook, JARVIS says so instead of pretending.

Email drafts are written by voice (“write an email”, “draft an email to John about Friday”) and shown in an on-screen review card that is also saved on this computer; approving opens the draft in your mail app — drafts are never sent automatically. Bare names are accepted as recipients (“John” advances the flow instead of repeating the question); add the address in the To field before approving. “Show me my email drafts” lists saved drafts. Sending through SMTP and reading the inbox need an account in the local .env file: JARVIS_SMTP_HOST, JARVIS_SMTP_USER, and JARVIS_SMTP_PASS (for Gmail use smtp.gmail.com with an App Password from Google Account > Security > 2-Step Verification > App passwords — never your normal password; optional JARVIS_IMAP_HOST, default imap.gmail.com, enables “summarize my emails”). Without an account, drafting, local saving, and review still work; sending and summaries honestly report what is missing.

The voice pipeline reports wake confidence, transcript, and command in the diagnostics panel; state names shown there include STANDBY, STANDBY · LISTENING FOR WAKE, ACTIVATED · LISTENING, PROCESSING, SPEAKING, and the RETURN TO STANDBY notice when the follow-up window expires. No microphone audio or transcripts are kept beyond the recent diagnostics log shown in the app.

Microphone capture, voice activity detection, wake phrase checks, and transcription run locally. JARVIS does not save microphone audio or send it to a cloud speech service. Each short phrase is processed by the local English model; CPU transcription can take a moment. The optional diagnostic panel shows the microphone, local recognizer state, final transcript, and recent pipeline events. If microphone permission is blocked, allow it in Windows Privacy & security > Microphone, then tap Enable Voice.

The existing offline Whisper runtime and the English base model are in `offline-asr`. Do not remove that folder. Voice & Listening Settings includes microphone sensitivity and Microphone & Audio Output. The selected microphone is used for local recognition; if a device does not open, choose another microphone or the Windows default. Raise sensitivity if JARVIS misses a quiet voice; higher gain can also pick up background noise. The selected output device is used for JARVIS spoken replies when the Edge audio-output API is available; browser and music audio keep their own output settings.

Speaking can be interrupted with “Jarvis, stop talking” or by saying “Jarvis” followed by another request. Microphone noise alone does not cut off JARVIS. Recognized audio matching recent JARVIS speech is ignored to reduce echo-triggered interruptions. “Stop the music” controls music playback; it does not stop JARVIS's voice. The INTERRUPT button remains available as a backup.

Local AI
--------
JARVIS uses Ollama on this PC for general conversation and tool-supported desktop requests. It never sends chat to a cloud AI provider. Open AI Settings and Refresh to detect Ollama and installed models. On computers with less than 32 GB RAM, JARVIS recommends qwen3:1.7b as a lighter starter (about 1.4 GB download). Open AI Settings and choose GET SMALLER MODEL to download it through Ollama and make it the preferred model. Systems under 8 GB RAM are recommended qwen3:0.6b. Keep Ollama running; no cloud chat provider is used. Test Model verifies an installed model before use. Saying “check AI status” (or “is Ollama running”) runs the same checks by voice or text: endpoint reachability at http://127.0.0.1:11434 (overridable with the JARVIS_OLLAMA_URL environment variable before starting the bridge), installed-model list, and a small timed generation probe. If Ollama is installed but stopped, the check starts the service once — and only if no Ollama process is already running — then reports the result.

Command understanding is hybrid. Simple commands (“what time is it”, “pause the music”, “open Calculator”) run on fast deterministic handlers and never touch the model for routing. Compound or referential requests (“find the Roblox folder and tell me what is in there”, “open that folder”) go to the local Ollama model with a planning protocol and real backend tools: file search (folder hits include a verified contents preview), directory listing by search-result ID, YouTube Music and YouTube search opening, web search, app and website opening, and the clock. The model works step by step within a bounded tool loop, must use exact returned IDs, and must say what was actually opened or found — playback is never claimed without verification, and file contents are treated as untrusted data. YouTube Music stays the default music service; “watch” requests use YouTube video results. Follow-ups like “open that folder” resolve against the most recent search. Say “research” plus a topic for deep mode (web search first, then a longer structured answer with thinking enabled). “Did I mention …” searches your saved notes and stored conversations with quoted evidence. Music search replies vary instead of repeating one line.

General questions, follow-ups, and current-information questions go to the selected local model. JARVIS keeps the Ollama model warm and caps replies to reduce delay. Answers should be short summaries; when web search is needed, sources are shown below the answer. Search results can be incomplete or blocked by the providers. “Search YouTube for …” opens a visible YouTube search; “Search the web for …” searches in the background.

Fish Audio voice
----------------
To change the voice, open Voice Engine → Change Voice in JARVIS. Paste the Fish Audio voice ID, enter the API key once, and choose Save Voice. Leave the key field empty when you only want to change the voice ID; JARVIS keeps the saved key. Preview Voice plays a sample. The key is written to the local, ignored .env file and is never returned to the interface. Do not paste API keys into chat. Fish Audio requires internet and may have account limits or charges. Choose Local Windows voice in the provider menu for offline speech output. You can also use Configure-Fish-Voice.bat to replace only the key.

Music
-----
“Open music” opens YouTube Music. “Play Magnetic by ILLIT” and other explicit “Play …” requests search there. Ordinary speech such as “Hey JARVIS, what is the weather?” is not treated as a song. Select the correct track in YouTube Music. Search does not bypass sign-in, Premium requirements, regional availability, or player start restrictions. JARVIS does not claim playback began just because it opened search results. Track controls (“pause”, “stop”, “stop what's playing”, “pause it”, “skip”, “next”, bare “play”/“stop”) reach the controlled Google Chrome player: an exact Chrome tab under tab control when available, otherwise the system-wide media keys, and the reply always says whether the result was verified. Volume up/down changes Windows system volume even when no browser media session is active. "Search YouTube for …" stays on regular YouTube. Every new song search opens or reuses a tab; without tab control old music tabs stay open, so close them or enable tab control to manage tabs by voice.

Media Orb
---------
A compact floating holographic panel appears near the bottom-center of the JARVIS window whenever the computer is playing media — a Chrome or Edge video, YouTube/YouTube Music, Spotify, a movie, a local player, game audio, Discord — and fades out a few seconds after the sound stops, with a grace window so buffering gaps never flicker it. It is not tied to JARVIS browser control: the media monitor listens to the Windows output mix on its own, so Chrome video appears even though Edge is the browser JARVIS automates, and it works with Edge closed. Titles, artists and the source are shown when Windows media sessions or the verified player report them; when nothing reports metadata the orb still appears and reads MEDIA ACTIVE. It keeps the playback progress bar when position is reported, transport controls (previous, play/pause, next), volume buttons, and an expand row. Click the orb to expand or collapse it, drag anywhere on its bar to move it (the position is remembered), and hover for a holographic highlight; the overlay never takes keyboard focus. Say “show the music player” to open it manually or “hide the music player” to dismiss it; a dismissed orb stays hidden until different media starts. All buttons call the same media actions as voice commands.

Live frequency visualization

The orb's movement is measured audio, never a decorative loop, and it needs no click, screen share or permission prompt. jarvis-audio-loopback.ps1 captures the default Windows render endpoint with WASAPI loopback and prints FFT frames (1024-point FFT at 30 fps: level, bass, low-mid, mid, high, peak/RMS dB and twelve log-spaced spectrum buckets). media-monitor.js starts that capture while the JARVIS window is watching, fans the frames out to the orb over /api/media/stream, and stops it again after 30 idle seconds so no capture session or helper process is left running; exactly one capture exists at a time. Frames are emitted on a fixed schedule even while nothing is playing, because WASAPI loopback delivers no packets during silence — skipping that made the orb freeze on its last frame and was the reason the orb stopped working at all. Silence therefore measures as real silence and the animation settles.

The measured values drive the layers: overall loudness sizes and brightens the core, bass and low-mids expand the inner ring, mid energy drives the outer ring, high frequencies drive the particles and the wave bars, and sharp transients flash the light pulse. This really does follow the audio: against the same mix, speech raised the high band from 0.001 average (bass-heavy music) to 0.165 average and 0.76 peak, while the low and mid bands stayed music-shaped. A quiet passage looks different from a loud one, and a sudden sound fires the pulse ring.

The orb never fakes what it has. With no capture it says AUDIO CAPTURE · CONNECTING or · UNAVAILABLE; with measured sound it says LIVE AUDIO · SYSTEM MIX; with the capture running but silence it says CAPTURE READY · NO SOUND and calms down; and if the capture stops delivering frames it says AUDIO CAPTURE · STALLED · RESTARTING instead of freezing. A watchdog in the monitor detects a capture that has gone quiet for more than ~1.5 s (a hung helper, a device change, a suspended audio service), kills it and rebuilds it — verified by freezing the capture process: the stall was detected in about two seconds and frames were flowing again about two seconds later. Windows media sessions (GSMTC) supply title/artist and precise transport when an app registers one; Chrome registered none on this machine, so nothing about appearing, animating or reacting depends on them. The tooltip on each control says whether it acts on a media session or falls back to the system media keys.

When something looks wrong, press DIAG in the orb's expanded row: it reports MEDIA MONITOR (connected/stalled), ACTIVE MEDIA, PLAYBACK, AUDIO CAPTURE (fps and sample rate), FFT, VISUALIZER (frames received and how long ago), and ORB WINDOW. The same numbers are on GET /api/media/status and under "media" in GET /api/health. The debug panel is only visible after pressing DIAG, so the normal HUD stays clean.

Alarms, reminders, and calendar
--------------------------------
Alarms and reminders are registered as per-item Windows Task Scheduler jobs and saved in `planner-data.json` beside the app. The alarm dialog has Snooze 10 Minutes and Dismiss buttons; saying “snooze for 10 minutes” or “turn off the alarm” can control an active JARVIS alarm while the bridge is running. Weekday alarms repeat Monday through Friday. JARVIS's local calendar stores event titles, local start/end times, locations, and optional reminders in the same file. It checks event overlaps; deleting a calendar event requires confirmation.

The local calendar is not connected to Google Calendar, Microsoft Outlook, or another account. Windows alarms can run while the JARVIS window is hidden or closed to the tray while the host remains running; scheduled task jobs also remain registered if JARVIS exits. Windows Task Scheduler may wake a sleeping computer only when hardware and power settings permit. No alarm can ring while the computer is shut down or powered off. Notifications and audible alarms require the Windows user session to be available and system sound enabled.

Browser tab control
-------------------
JARVIS can list, switch, open, and close individual browser tabs when tab control is connected. Google Chrome is the primary controlled browser. Say “enable browser control” and JARVIS opens a separate controlled Chrome window alongside your normal browser — your open tabs and work are never touched, closed, or restarted. (Older guidance about closing all browser windows no longer applies.) Then use “list tabs”, “switch to the next tab”, “what tab am I on”, “open a new tab”, “close the YouTube tab”, “close the second tab”, “close the tab playing music”, and “close this tab”. Say “browser control status” at any time: it distinguishes a connected session, an open-but-uncontrolled browser, and no browser at all. Chrome blocks tab control on normal windows, so JARVIS goes straight to the separate controlled window and says so. When tab control is off, “close this tab” sends the shortcut to the frontmost browser window (never the JARVIS window itself, and never without verifying focus first); the reply states that the outcome could not be verified instead of claiming a specific tab closed. Tab control never kills browser processes, and a closing failure is always reported as a failure. Say “open this song on YouTube Music” with no title and JARVIS asks which song instead of launching an app called “this song”.

Memory and recall
-----------------
JARVIS keeps saved notes in this app profile plus a durable conversation archive used only for recall. Commands: “remember that …”, “forget about …”, “what do you remember about me”, “search our conversations for …”, “what did we discuss yesterday”, “what did I ask you to do last time”, and “continue the project”. Passwords, API keys, and tokens are rejected as notes. Clear Chat only clears the screen; saved notes and the recall archive stay, so recall keeps working across sessions and screen clears. “Forget everything” asks for confirmation and then clears notes and the archive. When you ask a general question, the local model receives your saved notes and only the relevant archive hits for that question.

File search
-----------
“Find my homework”, “where did I save my project”, “find my latest file”, and “find pdf files from this week” search the Windows known folders (Desktop, Documents, Downloads, Pictures, Videos, Music) with exact matches ranked first and newest-first sorting when you ask for the latest. The top matches appear in the conversation; say “open it”, “open the second result”, or “open the last one” to open one. Opening a program or script (.exe, .bat, .cmd, .ps1, .msi, and similar) always asks for confirmation before it runs. “Open the downloads folder” opens the folder itself.

Multi-turn workflows
--------------------
Incomplete requests become short conversations instead of failures: “set a calendar event” asks only for the missing title, day, or time; “write an email” asks for recipient, subject, and body (say “skip” to leave the recipient empty); “message Alex” asks what to say. Email drafts and Discord messages always end in an on-screen preview card that must be confirmed on screen or by voice; nothing is sent automatically, and Discord messages require the preview confirmation even when the whole message was spoken. “Cancel” (or “never mind”) during a pending request aborts it without creating or sending anything, and an AI failure never clears the fields already collected.

Privacy and desktop actions
---------------------------
The app stores its profile, conversation, and explicit notes in the dedicated local Edge app profile. The planner stores local schedule entries in planner-data.json. The Fish key belongs in the ignored .env file only. Never expose it in screenshots or messages.

JARVIS can open registered websites and installed apps, search supported local folders, prepare an email draft for review, and show a confirmation before a Windows shutdown. Email drafts are not sent automatically. AI desktop tools use a validated allowlist and do not run arbitrary shell commands.

Verification notes
------------------
Automated tests cover wake parsing, website routing, conversation-history bounds, state transitions, alarm/event date parsing, memory notes and secret rejection, recall commands, multi-turn calendar/email/Discord workflow completion, email recipient handling and summaries, file-search parsing and ranking, echo suppression, tab-target close intents, browser tab matching, VAD noise adaptation, site-typo correction, Discord secret handling, the local server (file search, planner writes, alarm lifecycle, notification scheduling, drafts, confirmation gate, origin checks) on an isolated test port with a temporary calendar file, and browser tab-control honesty. Run them from the app folder with the files listed explicitly (the directory form fails on Node v24.20.0):

node --test tests/core.test.js tests/voice-improvements.test.js tests/memory.test.js tests/flows.test.js tests/files-tabs.test.js tests/server.test.js tests/browser-tabs.test.js tests/voice-echo-regression.test.js tests/calendar-music-tabs.test.js tests/phrase-expansion.test.js tests/email-voice-repair.test.js tests/file-calendar-repair.test.js tests/ai-orchestration.test.js tests/music-orb.test.js tests/music-orb-audio.test.js tests/media-monitor.test.js

The media tests synthesize spectra with a real DFT, drive the capture lifecycle with fake media devices, and cover the stall watchdog, the capture's startup window, and the orb's stale-frame handling, so they run without a browser or a sound card. The capture itself was verified here against real audio: Chrome playing a YouTube video drove the orb live with no Windows media session and no Edge involvement, synthetic speech measurably raised the high bands, and freezing the capture process made the orb report the stall and recover on its own. The offline speech engine can be tested without internet; actual microphone wake activation still needs a real microphone and Windows permission. Actual local AI inference requires Ollama and a downloaded model. Fish Audio voice playback requires a valid API key. The server test never opens programs or windows and never touches the real planner-data.json.
